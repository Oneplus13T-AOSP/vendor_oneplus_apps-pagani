# Pagani apps static audit — 2026-11-02

현재 결과는 앱 빌드와 정적 감사이며, ROM 빌드/플래시/13T 실기기 실행은 수행하지 않았다.
기존 out/target/product/pagani 산출물도 비교 자료로 사용했으나 향후 ROM 빌드의
정책/링커 네임스페이스/권한 부여 결과를 보장하지 않는다.

## 의존성과 ABI

| 앱 | 분석 가능한 ELF | 확인한 강한 외부 심볼 참조 | 기존 pagani out의 직접 DT_NEEDED 제공자에서 미발견 |
| --- | ---: | ---: | ---: |
| 문서 | 14 | 1397 | 0 |
| IR 리모컨 | 4 | 249 | 0 |
| 스캐너 | 17 | 2219 | 0 |

심볼 버전도 대조했고, Bionic IFUNC 표시를 일반 함수와 함께 처리했다.
이는 직접 의존성의 정적 대조다. 실제 linker namespace, JNI 등록, Java 메서드
해석, 선택적 dlopen, OEM Binder 서비스와 서버 인증은 실기기 확인 대상이다.

스캐너의 libsgmain.so는 원본 플러그인 ZIP이다. libsgmainso-5.4.171.so는
readelf가 동적 테이블을 정상 해석하지 못하는 보호된 ELF다. 이 두 항목의 내부
호환성을 위 심볼 검사 통과에 포함하지 않았다. 모두 원본 바이트를 보존했다.

모든 일반 JNI는 AArch64다. ELF LOAD 정렬이 4KB인 라이브러리는 문서 14개,
스캐너 10개, IR 2개다. ZIP 16KB 정렬 검사는 통과했지만 ELF 16KB 페이지 지원은
증명되지 않았다. 실제 커널 페이지 크기와 로더 동작을 확인해야 한다.

uses-library 목록은 ROM의 manifest_check.py로 검사했다. 스캐너의
com.coloros.statistics 등은 required=false이며, 선택적 선언이 런타임의 모든
OEM API 호출까지 선택적으로 바꾸어 주지는 않는다.
BaseOcrScanner/AIUnit 등 추가 서비스는 이번 세 앱에 포함하지 않았다.

## 권한과 SELinux

- 세 앱은 platform 서명 대상인 일반 product/app이다. sharedUserId와 persistent
  선언은 없다. 새 priv-app, privapp-permissions, init, sepolicy는 추가하지 않았다.
- priv-app 허용 목록 누락에 따른 부팅 오류를 새로 만드는 구성은 피했지만,
  platform 서명이 OEM 권한·AppOps·런타임 권한을 모두 해결하는 것은 아니다.
- 문서와 스캐너는 MANAGE_EXTERNAL_STORAGE, SYSTEM_ALERT_WINDOW 등을 요청한다.
  스캐너는 WRITE_SETTINGS도 요청한다. 실제 허용 상태와 사용자 승인 경로를 확인해야 한다.
- 문서의 MOUNT_UNMOUNT_FILESYSTEMS/INTERACT_ACROSS_USERS 계열,
  스캐너의 CHANGE_CONFIGURATION 등은 signature 계열 선언도 포함한다.
  ROM 내장과 일반 data/app 설치의 권한 부여 결과를 동일하게 간주하지 않는다.
- ColorOS의 safe.*, OPLUS_COMPONENT_SAFE, AI/클라우드/연동 권한 요청이 원본에
  남아 있다. 제공자와 서명 조건이 충족되지 않은 권한은 부여되지 않을 수 있다.
  이 요청을 남긴 것 자체와 해당 기능의 실행 성공은 별개다.
- IR의 TRANSMIT_IR는 현재 framework manifest에서 normal 권한이다.
  기존 common.mk는 android.hardware.ir-service.oplus와 consumerir 기능 XML을 포함한다.
  HAL과 /dev/oplus_consumer_ir용 기존 SELinux 규칙도 있다.
  앱의 표준 ConsumerIrManager → system_server → IR HAL 경로를 유지한다.
  앱에 IR 장치 노드 직접 접근 권한을 새로 부여하지 않았다.
- 현재 seapp_contexts에서 platform 서명 앱은 targetSdk에 따라 platform_app 또는
  platform_app_36 계열 규칙 대상이다. 최종 이미지의 mac_permissions/정책 결과와
  Enforcing 상태에서의 AVC denial은 아직 실기기 확인 전이다.

## 지정한 네 벤더 폴더와 블롭 중복

다음 폴더의 개별 파일 및 APK/JAR 내부 arm64 JNI를 이름과 SHA-256으로 비교했다.

- vendor/oneplus/oreality-pagani
- vendor/oneplus/pagani
- vendor/oneplus/sm8750-common
- vendor/oplus/camera

| 위치 | apps-pagani와 이름이 같은 블롭 | 바이트 비교 |
| --- | --- | --- |
| oreality-pagani | 없음 | 해당 없음 |
| pagani의 odm/lib64 | libDocRectification.so, libc++_shared.so | 모두 다른 버전 |
| sm8750-common의 odm/lib64 | libaiboost.so | 다른 버전 |
| OplusCamera.apk 내부 | 일치하는 JNI 경로 7개 | libtensorflowlite.so만 스캐너와 동일, 나머지는 다름 |
| OppoGallery2.apk 내부 | 일치하는 JNI 경로 7개 | 모두 다른 버전 |

카메라 APK와 이름이 겹치는 항목은 libgallery_fileextender.so, libnaiveEngine.so,
libopencv_java4.so, libscan_engine_decode.so, libc++_shared.so,
libaiunit_sdk_core.so, libtensorflowlite.so다.
갤러리 APK는 libaiboost.so, libgallery_fileextender.so, libnaiveEngine.so,
libopluslog.so, libCutoutEffect.so, libc++_shared.so, libaiunit_sdk_core.so다.

세 신규 앱 사이에서도 다음 3종의 이름이 겹친다. 모두 서로 다른 바이트다.

- 문서/스캐너: libaiunit_sdk_core.so, libc++_shared.so
- 스캐너/IR: libimage_processing_util_jni.so

각 앱의 product/app/<모듈>/lib/arm64에 별도로 설치하므로 기존 odm/lib64 또는
다른 앱의 JNI 설치 경로를 덮어쓰는 정의는 없다. 세 신규 모듈명도 기존 빌드 정의에서
중복 발견되지 않았다. 동일한 TensorFlow Lite도 앱 전용 로딩 경로를 유지했으며
공유 전역 라이브러리로 바꾸지 않았다. 이름만 같다고 다른 버전들을 합치면 안 된다.
지정한 네 폴더의 APK 19개는 manifest의 패키지 ID까지 확인했으며,
새 세 앱과 동일한 패키지 ID를 가진 기존 APK는 없었다.

## 아직 필요한 검증

문서 한글 조합/저장/재열기, 스캐너 촬영/보정/PDF/OCR, IR 코드 다운로드와 가전
송신을 실제 13T에서 실행하고, logcat의 Java 예외·linker 오류·권한 오류 및
Enforcing AVC를 확인해야 한다. 검사 통과를 모든 기능 정상 또는 최종 ROM 호환성
완료로 해석하지 않는다.

## 추출과 핀 재현성

- 실제 ROM의 extract-utils로 원본/패치 후 SHA-1 및 SHA-256을 검사했다.
- 원본 덤프에서 생성한 결과와, proprietary/가 없는 별도 폴더에서 다시 추출·빌드한
  세 앱 결과가 모두 고정 해시와 일치했다. 서명 전 결과이므로 개인 서명 키가 핀에 포함되지 않는다.
- 설치 테스트용 서명본은 별도 디렉터리에 생성하고 서명/인증서/ZIP 정렬과
  서명 전 APK의 전체 페이로드 보존을 검사했다.
- 잘못된 패치 후 SHA-1과 SHA-256을 각각 거부하는 검사를 통과했다.
- 암묵적 ADB 추출과 존재하지 않는 섹션은 거부한다.
- 소스 커밋 미리보기에서 모든 APK/JNI/개인 키가 제외되고, 추적 대상에
  100MB 이상 파일이 없는 것을 확인했다.

참고: [AOSP signature permission allowlist](https://source.android.com/docs/core/permissions/signature-permission-allowlist),
[privileged permission allowlist](https://source.android.com/docs/core/permissions/perms-allowlist),
[Android 16KB page sizes](https://developer.android.com/guide/practices/page-sizes).
